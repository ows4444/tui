	<p class="kicker">How it works</p>
	<h2>Three methods and a Program</h2>
</div>

<div class="split">
<div class="split-steps">

<ol class="steps-list">
	<li><strong>Model</strong> holds your state. Any value with <code>Init</code>, <code>Update</code> and <code>View</code> is one.</li>
	<li><strong>Update</strong> gets every key, mouse event and resize as a Msg, and returns the next Model plus any Cmd to run.</li>
	<li><strong>View</strong> returns a string. The Program diffs it cell by cell and writes only what changed.</li>
	<li><strong>Run</strong> takes over the terminal and restores it on every way out.</li>
</ol>

<p class="split-note">This is <code>ExampleNewProgram</code> from <code>example_test.go</code>, which <code>go test</code> runs. <a href="/program/">Running a Program →</a></p>

</div>
<div class="split-code">

```go title="counter.go"
type counter struct{ n int }

func (c counter) Init() tui.Cmd { return nil }

func (c counter) Update(msg tui.Msg) (tui.Model, tui.Cmd) {
	if k, ok := msg.(tui.Key); ok && k.Type == tui.KeyRunes {
		switch k.Text {
		case "+":
			c.n++
		case "q":
			return c, tui.Quit()
		}
	}
	return c, nil
}

func (c counter) View() string { return fmt.Sprintf("count: %d", c.n) }

func main() {
	if _, err := tui.NewProgram(counter{}).Run(); err != nil {
		fmt.Println(err)
	}
}
```

	<h2>Frequently asked questions</h2>
</div>

<div class="faq not-content">

<details>
<summary>What is tui?</summary>

tui is a terminal UI (TUI) framework for Go, at
[github.com/ows4444/tui](https://github.com/ows4444/tui). An application is a
Model with `Init`, `Update` and `View` (the Elm Architecture); `tui.NewProgram`
runs it, reads keys, mouse events and resizes, and redraws `View` with a cell
diff so only changed cells are written.

</details>

<details>
<summary>How do I install tui?</summary>

Run `go get github.com/ows4444/tui`. It needs Go 1.25 or later. It resolves to
the latest tagged release. Before v1.0 a release may change exported
identifiers; the changelog lists each one.

</details>

<details>
<summary>Does tui have any dependencies?</summary>

No. tui uses only the Go standard library: `go.mod` has no `require` directive,
and a test in `internal/archtest` fails if any package imports outside the
standard library and the module.

</details>

<details>
<summary>Which platforms does tui support?</summary>

Linux, macOS, Windows, FreeBSD, OpenBSD, NetBSD and DragonFly BSD. CI runs the
tests on Linux, macOS, Windows and FreeBSD; OpenBSD, NetBSD and DragonFly BSD
are cross-compiled. Other operating systems, including Solaris and illumos,
fail to build on purpose.

</details>

<details>
<summary>Does tui work with screen readers?</summary>

`tui.WithAccessible(true)` switches a Program to an append-only, unstyled
plain-text transcript that a screen reader can follow, and `WithAccessibleAuto`
turns it on for `ACCESSIBLE=1` or `TERM=dumb`. No run with VoiceOver, NVDA or
Orca is recorded yet, so screen-reader support is unverified. See
[Accessibility](/accessibility/).

</details>

<details>
<summary>How do I test a tui application?</summary>

The `tuitest` package runs a model in a real `tui.Program` against an in-memory
terminal: keys, pastes, resizes and messages go in, and the emulated screen
comes out as lines that can be compared against golden files. See
[Testing](/testing/).

</details>

<details>
<summary>What license is tui under?</summary>

MIT.

</details>

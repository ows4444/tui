## Why tui

<CardGrid>
	<Card title="The Elm Architecture" icon="seti:go">
		A Model has `Init`, `Update` and `View`. `Update` returns Cmds for side
		effects; the Program runs them and feeds the results back as Msgs.
	</Card>
	<Card title="Standard library only" icon="approve-check">
		`go.mod` has no `require` directive, and a test in `internal/archtest`
		fails if any package imports outside the standard library and this module.
	</Card>
	<Card title="Cell-diff rendering" icon="rocket">
		Each frame is parsed into a grid of cells and only the cells that changed
		are written, with relative cursor movement.
	</Card>
	<Card title="Widgets that compose" icon="puzzle">
		Inputs, tables, trees, dialogs, menus, pickers, charts and more. Every
		widget has a `LayoutNode()` adapter and an accessible `Linearize` form.
	</Card>
	<Card title="Layout and theming" icon="pencil">
		Flex, grid and overlay layout nodes. 16 preset themes, component tokens,

	</Card>
	<Card title="Accessible by design" icon="open-book">
		`WithAccessible` switches to append-only, unstyled output for screen
		readers; reduced motion follows `NO_ANIMATION` and `REDUCE_MOTION`.
	</Card>
	<Card title="Terminal-aware" icon="laptop">

## A complete program

```go title="counter.go"
type counter struct{ n int }

func (c counter) Init() tui.Cmd { return nil }

func (c counter) Update(msg tui.Msg) (tui.Model, tui.Cmd) {
	if k, ok := msg.(tui.Key); ok && k.Type == tui.KeyRunes {
		switch k.Text {
		case "+":
			c.n++
		case "q":
			return c, tui.Quit()
		}
	}
	return c, nil
}

func (c counter) View() string { return fmt.Sprintf("count: %d", c.n) }

func main() {
	if _, err := tui.NewProgram(counter{}).Run(); err != nil {
		fmt.Println(err)
	}
}
```

The model is `ExampleNewProgram` from the repository's `example_test.go`, which
`go test` runs. [Running a Program](/program/) covers the rest.

## Frequently asked questions

### What is tui?

tui is a terminal UI (TUI) framework for Go, at
[github.com/ows4444/tui](https://github.com/ows4444/tui). An application is a
Model with `Init`, `Update` and `View` (the Elm Architecture); `tui.NewProgram`
runs it, reads keys, mouse events and resizes, and redraws `View` with a cell
diff so only changed cells are written.

### How do I install tui?

Run `go get github.com/ows4444/tui`. It needs Go 1.25 or later. There is no
tagged release yet, so this resolves to a pseudo-version of the latest commit.

### Does tui have any dependencies?

No. tui uses only the Go standard library: `go.mod` has no `require` directive,
and a test in `internal/archtest` fails if any package imports outside the
standard library and the module.

### Which platforms does tui support?

Linux, macOS, Windows, FreeBSD, OpenBSD, NetBSD and DragonFly BSD. CI runs the
tests on Linux, macOS, Windows and FreeBSD; OpenBSD, NetBSD and DragonFly BSD
are cross-compiled. Other operating systems, including Solaris and illumos,
fail to build on purpose.

### Does tui work with screen readers?

`tui.WithAccessible(true)` switches a Program to an append-only, unstyled
plain-text transcript that a screen reader can follow, and `WithAccessibleAuto`
turns it on for `ACCESSIBLE=1` or `TERM=dumb`. No run with VoiceOver, NVDA or
Orca is recorded yet, so screen-reader support is unverified. See
[Accessibility](/accessibility/).

### How do I test a tui application?

The `tuitest` package runs a model in a real `tui.Program` against an in-memory
terminal: keys, pastes, resizes and messages go in, and the emulated screen
comes out as lines that can be compared against golden files. See
[Testing](/testing/).

### What license is tui under?

MIT.
